NAND Land has a simple LED blinker tutorial. They pretty much give you everything, but I used it as a launching ground to figure some things out myself.

I have a simple project setup in [GitHub](https://github.com/TheMikeste1/softfirmware/tree/master/nandland/led_blinker). It contains my version of the code from the tutorial, which is pretty much identical except for some naming and minor architectural differences. However, I've also organized it into a project-like structure and added some utility scripts. Additionally, I set it up to use VUnit instead of a hand-crafted testbench. VUnit allows me to write unit-like tests, and additionally handles sanitizing the circuit simulation in-between tests by restarting the simulation. I noticed the simulation output files, called wave files, can get very large very quickly, so this approach allows me to generate a wave file for just the test I'm working on.

Additionally, I have a small set up for OSVVM, which is a VHDL verification tool. It includes capabilities like coverage, edge case detection, and random tests. While this project doesn't benefit much from OSVVM, it will be useful for more complex circuits where comprehensive unit tests are not feasible. Another aspect random OSVVM testing has over traditional unit testing is it can test many complex transitions: far more than would be feasible through iterative testing. If the circuit were a state machine, OSVVM will eventually allow all states transitions to be tested without needing to enumerate every possible transition. From my perspective, this is the real power of OSVVM since I find its coverage utils rather lack-luster and honestly more geared towards this random testing over real coverage.

I also discovered some more in-depth syntax for VHDL that I find make the language more enjoyable. In particular, I discovered [[Component#Direct Instantiation|direct component instantiation]], which is considerably better than the indirect NAND Land used. I also set up an LSP and got GHDL and VUnit working through containerization and a "GHDL virtual environment," which seems to be easier and adaptable than installing locally.

Finally, I got GTKWave working. It was a bit of a pain in the beginning because anything but the dark theme does not seem to display correctly on my version of Linux. I also had an issue where the vhd and fst wave data files did not provide information for integer types, showing them as either a 1 or 0 instead of their actual value. I was originally using these files because my 16 GB system could not handle the size of wave files produced by NAND Land's testbench. With my VUnit set up and ghw via `run_vunit.sh --gtkwave-fmt ghw`, GTKWave now displays the correct values.
